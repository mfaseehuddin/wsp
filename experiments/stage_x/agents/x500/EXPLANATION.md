# EXPLANATION (agent x500)
## How the model works (about 15 lines)
1. It is a standard 8-layer causal transformer (d=672, 4 heads x 64, MLP 256, learned position table). Every weight was written from formulas; nothing was trained.
2. The residual stream holds named channels: one-hot tokens, token classes, "previous token" copies (p1: channels), flags (L_*), mode switches (m_*), and a 28-dim emit code.
3. Layer 0 heads fetch the previous token(s) and the newest token of each keyword class in the current turn (digit, operator, greeting, secret, delete...).
4. MLP rules turn those into intents (calc, greet, fact, name, read, delete, ...). Intents are flags that persist through the reply, because the newest USER token never changes.
5. Reply text is composed token by token. A frame is a chain of rules keyed on the last few tokens; each rule emits the next token by writing its code to the emit channels. Frames are at most 6 words.
6. Slots (a copied name, expression, file path, number, relation word) are filled by gated copy heads: a first-token head finds a flagged start position, then an induction head continues the span until it leaves its character class.
7. Facts (capital of a country) are rules on two flags (relation, entity) that emit the value word. The same flags feed the frame "The capital of X is Y." and the unknown path.
8. Arithmetic uses the calc tool: the model writes a JSON tool call, copying the expression from the user text (with plus/minus/times translated), then reads the RESULT number back by copying.
9. Unknown questions fall to the fallback frame "I don't know that yet." (emit strength 0.5, so any real intent beats it).
10. Safety lives in negations: secrets / ".." flags block the read rule and trigger a refusal frame; delete needs "yes" in the same message and no "no", otherwise it asks to confirm or cancels; text inside RESULT never raises a flag because flags are keyed to user tokens.
11. Memory: the name head has no turn-boundary key, so it finds the newest "I am X / name is X" anywhere in context; later corrections win by recency.
12. Limits: it only knows 20 capitals, calc, names, a few social phrases, exact-word echo and file read/delete. Repeated bigrams break copying (e.g. 11, te in notes/tell).

## Where things live
- Language: word list (116 words) + class rows of `embed` + frame rule chains (`rules.social.*`, `rules.fact.frame`, `rules.name.*`).
- Facts: `rules.fact.known` and `rules.fact.value` (two neurons per fact, in layers 3-4).
- Memory: head `latest.name.first` (no USER null key) + `induct.name.cont`.
- Safety: `rules.safe.*`, negation lists on `rules.tool.*`, `rules.tool.delete`.
- Tools: `rules.calc.*`, `rules.tool.*`.

## Edit map
- Add a capital: append (Country, City) to `CAPITALS` in `modules()`; it registers both words, adds the class rows, the E_ flag value row in head `ent1` (max 64 entities per head) and two rules.
- Add a word: call `wid(S, "word")`; to make it a keyword add it to a `tokclass` list.
- Add a frame: `frame(S, tag, trigger_conds, parts, tagconds, negs)`; parts are strings (words if registered, else bytes); keep it at most 6 words.
- Add a tool: copy the `tool.read` block: a JSON prefix chain, a start-flag rule, a mode rule, a close chain.
- Add an intent: one flag head or a class in an existing `flag.*` head (`latest(...)`), one rule setting a flag, one `frame`. Add the new flag to `negs` of `fallback`.

## Limits
No free-form generation, explanation, ordering, syllogisms, word problems, uppercase, lists or supplied-fact answers. Copying fails on repeated bigrams inside a span. "Done." after delete does not check whether the tool succeeded. The model is a rule machine in transformer form, not a language model.

### latest.flag.digit.L0h1.k
Latest-of-class head. Key score = 1e6 for tokens of the class (and for BOS/USER) plus a recency term (3e5 * sin(w t - 0.3), w about 1e-4), so the newest flagged token wins by e^30 per token. USER tokens are "null" keys, which makes the flag turn-local: an older turn loses to the newest USER. Gated copy heads drop the null keys and add a BOS sink whose score is lowered by the mode channel, so the head only writes when its mode flag is on. Value = a flag channel (L_x) or the token code of the winner (the copy). Tensor `layers.0.wk`. Why: USER/BOS tokens are null keys so.

### unembed
Decodes the 28-dim emit code: logit(v) = 20 * cos(code(v), emitted code). Greedy argmax therefore picks the emitted token; END has a bias of 3 so an empty turn ends. Tensor `unembed`. Why: greedy argmax picks the emitted token.

### b_unembed
END logit 3 = default stop when no rule fires. Tensor `b_unembed`. Why: when nothing fires the turn ends.

### pos
Learned position table: 16 sin/cos pairs for shift heads and one slow pair for recency. Everything else is zero, so no positional noise reaches the feature channels. Tensor `pos`. Why: sin/cos pairs only.

### embed
One-hot token channel (amplitude 32) plus class flags (digit, operator, name letter, path char, ...). Classes are the lexicon: add a token to a class by setting one embed entry. Tensor `embed`. Why: identity and class available from layer.
