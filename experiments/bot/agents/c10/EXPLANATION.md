# c10: a hand-written IT help-desk bot that follows scripts

## How the bot works (plain language)
1. Every bot turn follows a fixed **script**: a FAQ answer, a greeting, opening a ticket, and so on. There are 11 scripts.
2. The bot reads the current user message and lets each **keyword** cast weighted votes, for example "vpn" means the vpn topic and "urgent" means paging a team. The votes are averaged over the current message only.
3. The winning script is written into the private think area as a **codeword**, a rare dictionary word such as `jackleg` (FAQ) or `jiva` (escalate). For FAQ and urgent turns, a second codeword names the topic, such as `katun` for vpn.
4. These codewords stay in the conversation, so later turns can look back at them. "It still fails" reuses the topic of the last FAQ turn.
5. Each next word is then a table lookup: given (script, topic, current word, previous word), exactly one MLP unit fires and writes the next word.
6. Values that must be **copied**, such as a ticket id, a user name, a service, or a tool result, come from an attention head that the lookup switches on. It fetches the most recent word of the needed kind.
7. A topic's team ("vpn → network") is a small table from the topic codeword to the team word.
8. Nothing is trained. Every number comes from the knowledge base (`kb`) or from my hand-written keyword list.

## The parts
The model is 2 layers, d_model 219, 4 heads of size 41, an MLP of 306 units, learned positions, no LayerNorm, and biases on. The residual stream is split into named slots (column ranges):
POS 0-2 · TURN 3-4 · CURC 5-27 · FL 28-45 · PREV 46-86 · KCUR 87-97 · TCUR 98-119 · VOTE 120-152 · OUT 153-193 · SELFG 194-211 · ALLOW 212-218.

- **Word features (embed).** Each output word gets a unique (colour c, group g) pair. Inside any one script, all fixed words have different colours. `embed[w, CURC+c] = 1`. Special tokens and word classes (ID, USER, SERVICE, STATE, STATUS, TOPIC, TEAM, isK, isT) are 0/1 flags in FL. Copyable words also carry their group in `SELFG+g`. Codeword j has `embed[w, VOTE+j] = 1`. Keyword votes are added into VOTE.
- **Positions (pos).** These are cos(ωt), sin(ωt) with ω = 2π/300, plus a ramp t/256.
- **L0 H0, previous-token head.** The query is the key rotated by one step, scaled by 1.5e5, so the score peaks sharply at t-1 (a margin of about 33 logits). It copies CURC and FL of token t-1 into PREV.
- **L0 H1, turn head.** It attends to the most recent `<user>` (score 1000·flag + 5·position) and copies that token's (cos, sin) into TURN. This tags every token with "which user turn I belong to".
- **L0 H2 / H3, codeword heads.** They attend to the most recent K codeword or T codeword (score 4000·flag + 5·position, with `<bos>` at 2000 as a fallback). They copy its one-hot into KCUR or TCUR, which gives the current script and the current topic.
- **L1 H0, vote head.** The score is 2000·cos(difference of TURN codes), so keys in the same user turn tie and older turns are about 60 logits lower. The head averages the VOTE vectors of the current turn, and the unembedding reads VOTE straight onto the codewords. The `unknown` codeword gets bias +0.005, so it wins only when no keyword is present.
- **MLP units (both layers).** There is one unit per script step. The input weight is 1 on each condition (KCUR script, TCUR topic, CURC or FL of the current word, PREV of the previous word), and the bias is −(k−0.5). The unit therefore outputs 0.5 only if all k conditions hold, and 0 otherwise.
  - Ordinary units write 200 to OUT[c] and OUT[C+g] of the next word. The unembedding sums OUT[c] and OUT[C+g], so the target gets 200 and any other word gets at most 100.
  - Copy-slot units instead set ALLOW[class] = 1. These must sit in layer 0, because the copy head in layer 1 reads them.
  - Two kinds of "suppress" unit write −50 to the other half of VOTE. At the `<think>` position this lets only scripts compete; right after `jackleg` or `jungli` it lets only topics compete. These units sit in layer 1, so the −50 never leaks into later averages.
  - Units 261-304 of layer 1 are gates (261+j: topic j, 283+j: team of topic j): ALLOW[TOPIC] or ALLOW[TEAM] together with TCUR[j] writes the topic word or its team.
- **L1 H1, gated copy head.** The query is 10000·ALLOW[X], and the key is the class-X flag plus recency. A `<bos>` sink at 5000 absorbs the attention when nothing is allowed. The head copies the (c, g) code of the most recent class-X token into OUT, times 100.
- **Unembedding.** OUT[c] and OUT[C+g] each map to word w with weight 1. VOTE[j] maps to codeword j. `b_unembed` is −1, except 0 for codewords.

## Where knowledge lives (edit map)
All of these are generated by `weights.py`. Edit the named Python table and rebuild, or edit the tensors listed.
- **A FAQ reply:** `kb.FAQ` text → `units()`. These are the layer-0/1 `w_in` columns and `w_out` rows of the units whose condition includes TCUR[topic] and KCUR[faq], one unit per reply word. Changing a word means changing that unit's `w_out` (OUT[c], OUT[C+g] of the new word) and the next unit's CURC or PREV condition.
- **A topic keyword:** `TOPIC_KW` → `embed[word, VOTE+11+topic]` and `embed[word, VOTE+0]` (the FAQ script), both set to the weight.
- **An intent keyword** (urgent, still, down, …): `INTENT_KW` → `embed[word, VOTE+script]`.
- **Team of a topic:** `kb.FAQ[topic][0]` → `layers.1.w_out[283+j]`, the gate unit for TEAM with topic j, which writes the team word's (c, g).
- **Help-desk number (4357):** it is a reply word. Find it in the `locked` and `mfa` replies, i.e. the unit whose `w_out` writes code("4357"), and point it at the new number's code.
- **A tool name:** the unit (script, cur=`<tool>`) writes the tool word's code. A new tool is a new script in `scripts()`.
- **A new topic:** add a T codeword (a VOTE column and a TCUR column; each needs one spare dimension, or reuse a filler codeword), keywords, reply units, and one TOPIC and one TEAM gate unit.

## Limits
- **Parameters:** 1,491,920 (only about 9,000 are non-zero). The embedding and unembedding are 2 × 438k.
- **Keyword spotting is only as good as the hand list.** New phrasings with no listed word are answered "sorry, i can only help…".
  - A greeting combined with a problem gives the FAQ answer.
  - A sentence with two topics is decided by summed weights.
  - "help" counts towards escalation, so "can you help with vpn" opens a ticket.
- **Ties** between topics are broken by vocabulary order.
- **Escalating with no earlier FAQ turn** has no topic to use, so the slot is garbage.
- **Copy slots take the most recent matching word.** A user who names two services or two ids gets the later one.
